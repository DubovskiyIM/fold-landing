A domain runtime for AI agents

Stop giving AI agents API keys. Give them a domain.

Fold is the runtime layer where an AI agent knows what it can do, why it can’t, and what happens if it tries — before the call, not after the database is gone.

On April 25 2026 a Cursor agent powered by Claude Opus 4.6, working on a credential mismatch in PocketOS staging, found an unrelated API token, decided to delete a Railway volume to fix things, and wiped the production database and all volume-level backups in 9 seconds. The system never told the agent what it was allowed to do, why it shouldn’t, or what would happen if it tried. Fold is the layer that does.

What Fold does

Three properties, one declarative artifact.

No code-gen. No middleware to maintain. Author the IDF artifact once — every reader (UI, voice, agent, document) sees the same domain.

01
Declarative, not imperative
Describe entities, intents, invariants, role scopes, irreversibility points in one IDF artifact. The runtime enforces. No if(role==="admin") spaghetti. Add a new role tomorrow — every reader sees it.
02
Structured rejections, not 422s
The agent receives { error, reason, failedCheck, details }. Not “Internal Server Error.” Not a string. A JSON shape the LLM can read and adapt to. Agent scales the order down, retries, succeeds.
03
Irreversibility as a primitive
Mark an effect __irr.point="high" and the runtime blocks α:remove on anything past it. Forward-correction only. By construction, not by guardrail. Cursor-style “agent decided to delete production” becomes unreachable.
Class of guarantee

Irreversibility is a constructor, not a reviewer.

Most agent-safety layers are observers — they see a call, decide whether to let it through, log the rest. That’s the “guardrail” class. Irreversibility-as-a-primitive is a different class: it’s a property of the effect itself, baked into the runtime’s reducer. You can’t bypass a property. No “skip-guard” flag, no emergency override path, no admin role that gets to delete the unloggable.

Irreversibility primitive

A property of the effect in Φ.

Enforced by
A branch in the runtime’s reducer — not a check on top of one.
Bypassed by
Editing the IDF artifact and landing the change through PR review. Nothing else.
What survives
Forward-correction always (α:"replace"). Erasure of high-irr effects: never.
The branch, verbatim from idf/server/validator.js
// Step 4 — irreversibility check, runs on every effect. // α:"remove" is blocked when target's history contains a confirmed // effect with __irr.point === "high" && at !== null. // Forward-correction via α:"replace" is always allowed. if (effect.alpha === "remove" && ctx.id && !effect.target.startsWith("drafts")) { const { hasIrreversiblePast } = require("./irreversibility.cjs"); const historyRows = db.prepare( "SELECT context FROM effects WHERE status = 'confirmed' AND context LIKE ?" ).all(`%"id":"${ctx.id}"%`); if (hasIrreversiblePast(historyRows)) { return { valid: false, reason: "irreversible_point_passed" }; } } // irreversibility.cjs — the predicate, no configuration surface. function hasIrreversiblePast(history) { for (const ef of history) { const irr = getIrreversibility(ef); if (irr?.point === "high" && irr.at != null) return true; } return false; }

This is not a check you turn on. It’s a branch in the reducer. Removing it requires shipping a new runtime build — not flipping a toggle in your config, not setting an env var, not adding an admin role. The space of bad effects isn’t a denylist your guardrail might miss; it’s empty by construction.

To make an effect mutable, the artifact author edits __irr.point at declaration time, before the effect is confirmed — reviewed in code, not toggled at runtime. Compare: SQL constraints (not application validation), type safety (not runtime asserts), capability security (not POSIX rwx).

What you write

The artifact, in fifteen lines.

The runtime reads one declarative artifact — entities, intents, role scopes, preapproval predicates. Below: an excerpt from the invest demo domain. No DSL, no codegen — plain JS objects the runtime folds into an event log.

// invest/intents.js — what the agent is allowed to call intents.agent_execute_preapproved_order = { base: "create", forRoles: ["agent"], parameters: { side: { type: "select", options: ["long", "short"] }, quantity: { type: "number", required: true }, ticker: { type: "ref", entityRef: "Asset" }, }, particles: { effects: [ { α: "create", entity: "Order", fields: "$params" }, ]}, }; // invest/ontology.js — what the agent is allowed to do, declaratively roles.agent = { base: "agent", canExecute: ["agent_execute_preapproved_order"], preapproval: { required: true, predicates: ["active", "notExpired", "maxAmount", "dailySum"], }, };

That’s it. The runtime turns this into the /api/agent/invest/exec/* endpoint, the MCP tool description Claude reads, the structured 403 above, and the irreversibility guard. Same artifact powers four readers: UI, voice, agent, document. Author it once, no scaffolding to regenerate when the domain changes.

How long does the artifact take?
invest 14 entities · 61 intents · 5 invariants · ~600 lines a weekend, hand-written
gravitino 253 entities (Apache catalog OpenAPI) · 120 intents imported in <1h, enriched in 2d
workflow 9 entities · 47 intents · timer queue · cascade rules a day
Where the speed comes from
  • idf import postgres — reads your live schema, generates entity baseline with FKs and column types as fieldRole.
  • idf import openapi — reads your existing API spec, generates intents + parameter shapes + reference fields. This is how a 253-entity domain gets bootstrapped.
  • idf import prisma — same story for ORM-driven backends.
  • idf enrich — LLM pass to fill label, fieldRole, compositions, suggested roles.agent.preapproval predicates from your existing code comments.

How it plugs in. Fold is a sibling service over an HTTP API the runtime exposes from your IDF artifact — not middleware in your existing app, not codegen at runtime. Your current backend stays where it is; the IDF artifact describes the agent-facing surface, and the runtime serves it on its own port. The MCP server is a stdio adapter Claude Desktop / Cursor / Zed connect to.

Without Fold: a 200 OK. Position created. $50,000 of someone else’s money moved before any human saw it.

Who is this for

Not a chatbot toolkit — if you’re shipping PDF summarisers, LangChain or the Anthropic SDK is closer.

You’re the engineer at a 5–30-person team putting an AI agent into production this quarter — on top of a real backend, with real customers, real SOC2 Type II review on the horizon. You’ve read the PocketOS post-mortem, the Amazon Kiro 13-hour outage write-up, the Cursor-deletes-Replit-database thread. You don’t want a guardrail layer that reviews after the fact. This is for you.
